## [Bun rewritten from Zig to Rust](https://simonwillison.net/2026/Jul/8/rewriting-bun-in-rust/#atom-everything) ⭐️ 8.0/10

Jarred Sumner announced the complete rewrite of the Bun JavaScript runtime from Zig to Rust, leveraging AI coding agents to automate much of the porting process. The rewrite was motivated by persistent memory safety bugs in Zig, such as use-after-free and double-free errors, which Rust's type system inherently prevents. This rewrite demonstrates that large-scale software rewrites, long considered too risky, are now feasible with the help of AI coding agents and comprehensive test suites. For Bun users, it means improved stability and memory safety, while the broader software engineering community gains a case study in agent-driven migration. The rewrite cost approximately $165,000 in API tokens (5.9 billion input, 690 million output, 72 billion cached reads) and took about 11 days of agent execution. The new Rust implementation has been live in Claude Code since June 17, 2025, with 10% faster startup on Linux and no noticeable behavioral changes.

rss · Simon Willison · Jul 8, 23:57

**Background**: Bun is a fast all-in-one JavaScript runtime, bundler, and package manager designed as a drop-in replacement for Node.js, using JavaScriptCore instead of V8. Zig is a systems programming language with manual memory management, which Bun originally used but encountered a high number of memory-related bugs. Rust offers compile-time memory safety guarantees through its ownership and borrowing system, making it an attractive choice for reducing crashes.

## [IMGNet: Face Verification via Sign Pattern Matching](https://www.reddit.com/r/MachineLearning/comments/1urxvxh/i_built_imgnet_a_face_verification_model_that/) ⭐️ 8.0/10

An independent researcher from Indonesia built IMGNet, a face verification model that replaces cosine similarity with sliding window sign pattern matching, achieving 96.27% on LFW with a 10.58 MB FP32 model trained on CASIA-WebFace (490k images). When applied to ArcFace embeddings without retraining, IMG Sign Score achieves 99.58% on LFW, only 0.24% below the baseline. This method challenges the dominance of cosine similarity in face verification and demonstrates that relational sign patterns within embeddings can achieve competitive accuracy with a much smaller model, potentially enabling more efficient and interpretable face recognition systems. IMGNet introduces three key components: the SW Block (a multi-scale relational operation over prime window sizes {3,5,7}), the IMG Sign MSE Loss defined purely over sign pattern agreement, and a voting system that combines three complementary metrics (IMG Sign Score, AMP IMG Score, Chain Score). The model uses a single threshold across all metrics and shows improved training stability (±0.40% variance vs ±2.25% over epochs 29–50).

reddit · r/MachineLearning · /u/img-_- · Jul 9, 18:00

**Background**: Face verification determines whether two face images belong to the same person, typically by extracting embedding vectors and comparing them using cosine similarity. Cosine similarity measures the angle between vectors, capturing global directional alignment but ignoring local relational patterns. IMGNet instead examines sign patterns across overlapping windows of the embedding, focusing on local relational consistency rather than absolute vector values.

## [No Leap Second at End of 2026](https://datacenter.iers.org/data/latestVersion/bulletinC.txt) ⭐️ 7.0/10

The International Earth Rotation and Reference Systems Service (IERS) announces in Bulletin C that no leap second will be introduced at the end of December 2026. This announcement assures system administrators and timekeeping engineers that no disruptive adjustment to UTC will occur at that date, avoiding potential issues with software relying on continuous time increments. The last leap second was a positive leap second introduced in UTC at the end of December 2016, meaning there have been no leap seconds for nearly a decade. The IERS typically announces leap seconds about six months in advance to maintain the difference between UTC and UT1 within ±0.9 seconds.

hackernews · ChrisArchitect · Jul 9, 14:16 · [Discussion](https://news.ycombinator.com/item?id=48846281)

**Background**: Leap seconds are adjustments made to Coordinated Universal Time (UTC) to keep it within 0.9 seconds of mean solar time (UT1), which is based on Earth's rotation. Earth's rotation is irregular due to tidal friction, geological activity, and other factors, making leap seconds unpredictable. The International Earth Rotation and Reference Systems Service (IERS) monitors Earth's rotation and decides when to add or remove a leap second.

## [llm-meta-ai 0.1 Plugs Muse Spark 1.1 into LLM](https://simonwillison.net/2026/Jul/9/llm-meta-ai/#atom-everything) ⭐️ 6.0/10

Version 0.1 of llm-meta-ai, a plugin for the LLM command-line tool, has been released, enabling users to run prompts against Meta's new muse-spark-1.1 model via the Meta AI API. This plugin makes it easy for developers and researchers to experiment with Meta's latest model directly from the terminal, streamlining workflow and expanding the ecosystem of LLM plugins. It also marks the first API-accessible Spark model, potentially increasing adoption. The plugin is hosted on GitHub under simonw/llm-meta-ai and integrates with the LLM tool by Simon Willison. Muse Spark 1.1 was announced on July 9, 2026, and offers improved agentic tool calling and computer use capabilities compared to its predecessor.

rss · Simon Willison · Jul 9, 16:12

**Background**: LLM is a popular open-source command-line tool for running prompts against various large language models, supporting a plugin system for adding new models. Meta's Muse Spark 1.1 is the latest iteration of their Spark series, following the initial release in April 2026, and is designed for advanced reasoning and multimodal tasks. The model is accessible via a new API, positioning it as a competitor to models like Claude and GPT.
